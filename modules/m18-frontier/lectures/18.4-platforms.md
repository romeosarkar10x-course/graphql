## Concept (15 min)

### Three families

| Family | Examples (licence, version checked 2026-11-23) | The API comes from |
| --- | --- | --- |
| Generated from a database | PostGraphile 5.2.1 (MIT), Hasura graphql-engine v2.51.9 (Apache-2.0), Supabase pg_graphql v1.6.3 (Apache-2.0, a PostgreSQL extension) | tables, keys, functions; behaviour and permissions in config or SQL |
| Graph databases with GraphQL | Neo4j GraphQL Library (Apache-2.0), Dgraph v25.5.1 (Apache-2.0) | type definitions mapped to a graph store |
| Hosted logic on a central schema | Airbnb's Viaduct v3.0.0 (Apache-2.0, JVM) | one schema, resolvers hosted inside it, calling each other through GraphQL fragments ("re-entrancy") |

Plus code-first libraries in neighbouring languages, such as graphql-kotlin 11.1.0 (Apache-2.0; Module 15.10
used 11.0.0).

### What generation gives, and what it takes

PostGraphile's "amber" preset (measured in lab 18.4): connections with `totalCount` and cursors, global object
identification, foreign keys as fields, `orderBy` and `condition` on indexed columns only (no `RATING_DESC`:
`rating` has no index), and CRUD mutations for every table. Its names are the database's (`readerByOwnerId`),
its nullability almost (the owner relation is nullable although `owner_id` is NOT NULL), its authorization
PostgreSQL's row-level security, and its server options have no depth or cost limit. Error masking is on, which
hides even a client mistake: it runs graphql-js 16.15, which lacks the September 2025 rule *Operation Type
Existence* (5.2.1.1), so a mutation sent to the read-only API comes back as a masked planning error.

The trade: speed and consistency, against the database becoming the API contract. Module 7's evolution rules
(deprecate, then remove) do not survive a column rename.

### Viaduct

Airbnb's data-oriented service mesh: a central schema, business logic hosted in it (`@resolver` fields in
Kotlin or Java), resolvers composing through GraphQL. It is the alternative to federation when a company wants
one graph and one runtime. Its starter (`viaduct-dev/cli-starter`) builds with Gradle upstream, and runs on the
course image's Java 25: one Kotlin resolver, a schema in `src/main/viaduct/schema`, `Hello, World!` in about 4 s
once Gradle has its downloads. Lab 18.4 asks you to run it and compare.
