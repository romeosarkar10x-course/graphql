# 18.2 An MCP server in Java

## Hook (2 min)

The quickest way to give an assistant Shelfie is one tool, `run_graphql(query)`. It works in ten minutes. It also
lets the assistant run `deleteReview`, introspect everything, and fan out until the database begs.

## Concept (15 min)

### MCP in one page

The Model Context Protocol is JSON-RPC between a client (the assistant's host) and a server (your tools). The
course's server speaks the **Streamable HTTP** transport at `/mcp`:

1. `initialize` (POST): client and server agree a protocol version; the server returns `Mcp-Session-Id`.
2. `notifications/initialized`, then every request carries `Mcp-Session-Id` and `MCP-Protocol-Version`.
3. `tools/list`: each tool's name, description and JSON Schema for its input.
4. `tools/call`: name and arguments; the result is content (text) and `isError`.

Responses come as plain JSON or as a server-sent events stream (`data:` lines); a client must read both.
Batching JSON-RPC requests was removed in protocol version 2025-06-18. The current protocol version is
2026-07-28; the course's stack (Spring AI 2.0.2, MCP Java SDK 2.1.0) negotiates up to 2025-11-25
(`_workbench/2026-11-23-m18-probe/mcp-server/versions.txt`).

### Curated operations, not "execute anything"

Apollo's MCP Server, the reference design in this module's sources, turns persisted operations into tools (from
its documentation; not run in this course). The
idea transfers to any stack: an agent gets typed tools that each run one known document, and cannot select a
field the operations do not select. Cost is known in advance; reviews are code reviews.

### Spring AI

`spring-ai-starter-mcp-server-webmvc` (Spring AI 2.0.2, built on Boot 4.1.2, runs on the course's 4.2.0):

```java
@Tool(name = "book_details", description = "One book by id (e.g. b1) ...")
public Map<String, Object> bookDetails(@ToolParam(description = "Book id, e.g. b1") String id) {
    return shelfie.documentName("BookDetails").variable("id", id).executeSync().getData();
}
```

A `ToolCallbackProvider` bean (`MethodToolCallbackProvider`) turns `@Tool` methods into MCP tools; the
parameters become the input schema (with `additionalProperties: false`), so a missing required id is a tool error
before your code runs. `GraphQlClient.documentName("BookDetails")` loads `graphql-documents/BookDetails.graphql`:
Spring's persisted-operation idiom, with a `DocumentSource` that strips descriptions for graphql-java.

Two gotchas met while building the lab: Boot binds the environment variable `SHELFIE_URL` onto a property named
`shelfie.url`, so pick another name; and an unknown `Mcp-Session-Id` gets the 404 the transport spec requires,
but with a serialized Java exception and stack trace in the body.

1. Its name, its description and a JSON Schema for its input.
2. Shelfie's graphql-java 26.1 rejects descriptions on operations, which the September 2025 edition allows.
