# 18.6 Porting to another language

## Hook (2 min)

Since Module 1 every lab shipped a contract that does not mention Java. Today a TypeScript reviews subgraph joins
Java's catalog and clubs and Kotlin's accounts in one supergraph, and the same Hurl file grades it.

## Concept (15 min)

### The contract is the source of truth

A port is done when the contract says so, not when it looks right:

- **the API:** the same field signatures from introspection (lab 18.6 compares 15, nullability included);
- **the data:** the same seed (`contract/port/seed.json`, exported from the Java subgraphs);
- **the behaviour:** the same Hurl file, unchanged (`port.hurl`: the subgraph alone, then through the router);
- **the graph:** it composes with the other subgraphs and the router serves it.

The Java subgraph passes `port.hurl` too. A contract only its new implementation passes is a description of that
implementation.

### What did not carry over (measured)

| Difference | Fix |
| --- | --- |
| Pothos makes every field nullable by default | `defaultFieldNullability: false`, then `nullable: true` on three fields |
| Introspection lists arguments alphabetically | harmless for named arguments; the contract compares them sorted |
| `externalRef` types print `@extends`; a hand-written import list missed it | let Pothos compute the list; link Federation v2.9 |
| `@apollo/subgraph` 2.15.0 dropped an export the Pothos plugin imports, inside its declared `^2.0.0` range | pin 2.14.4 |
| Java prints `@key(fields : "id", resolvable : true)` | the Hurl regex allows both spellings |
| Spring's `ErrorType.UNAUTHORIZED` | a `GraphQLError` with `extensions.classification`, which Yoga does not mask |

### Idioms

Spring's `@EntityMapping` receives the whole list of representations; Pothos's `resolveReference` is called
once per representation (`@apollo/subgraph` maps them one by one), so a port backed by a database needs a
DataLoader to keep Module 15's "one store query". Virtual threads become `async`; the reader comes from Yoga's
`context` function instead of a `WebGraphQlInterceptor`.

### Numbers

On one machine, 1,000 requests at concurrency 4 after warm-up: Java (C1 only, 192 MB heap cap) starts in 986 ms,
TypeScript in 170 ms; 173 MB against 141 MB resident; p95 1 ms for both. At this size, startup is the visible
difference.

## Check

1. Why must the Java subgraph pass `port.hurl` as well?
2. Which difference did the signature check catch that Hurl alone would not have?
3. Why does a Pothos port need a DataLoader where the Java subgraph did not?

<details><summary>Answers</summary>

1. Otherwise the file describes the port, not the contract; the Java run proves the checks are the API's.
2. Nullability: the data was identical, so every Hurl assertion passed, but `id: ID` and `[Review!]` are a
   different API.
3. `resolveReference` runs once per representation, so without batching each entity is its own store query.
