# 5.5 Instrumentation

## Hook (2 min)

`Query.clubs` takes 808 ms. Or 62 ms. Both numbers are true; they answer different questions.

## Concept (15 min)

### Hooks around everything

`Instrumentation` has a `begin...` hook for parse, validation, execution, each object, each field's
execution, each field's fetch and each completion. A hook returns an `InstrumentationContext` whose
`onCompleted` runs when that step finishes, async fetchers included. Extend
`SimplePerformantInstrumentation` and override only what you need.

| Hook | Measures | For `Query.clubs` (lab 5.5) |
|---|---|---|
| `beginFieldFetch` | the fetcher alone | 62 ms |
| `beginFieldExecution` | fetch plus completing the whole subtree | 808 ms |

Fetch time finds the slow field; execution time finds the expensive subtree.

### State per request

`createStateAsync` runs once per execution; its result is handed to every hook of that execution. A
static map would mix concurrent requests together.

### Chaining and changing

`ChainedInstrumentation(List.of(a, b))` runs several. Hooks can also change things:
`instrumentDataFetcher` wraps fetchers (lab 5.2's tracer, lab 5.5's latency injector) and
`instrumentExecutionResult` can add `extensions`. Frameworks build their metrics and tracing on exactly
these hooks (Module 15).
