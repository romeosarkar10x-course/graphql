# 2.3 Aliases and multiple root fields

## Hook (2 min)

Product wants a "compare two clubs" screen. REST answer: two requests or a new
`/clubs/compare?a=&b=` endpoint. GraphQL answer: one document, if you can ask for `club` twice.

## Concept (12 min)

### Many root fields

A query may select any number of root fields; they run independently and come back side by side:
`{ hello clubs { name } }`.

### Aliases

An alias renames the response key: `left: club(id: $a)`. It is the only way to select the same field
twice with different arguments, and it works at any depth and on scalars:

```graphql
query CompareClubs($a: ID!, $b: ID!) {
  left: club(id: $a) { name currentBook { rating: averageRating } }
  right: club(id: $b) { name currentBook { rating: averageRating } }
}
```

### Response-key collisions

Two fields with the same response key must be mergeable: same field, same arguments. Otherwise the
response would need two values under one key, so validation (spec: *Field Selection Merging*) rejects it:

| Document | Result |
|---|---|
| `{ x: club(id: "c1") { name } x: club(id: "c2") { name } }` | `FieldsConflict : 'x' : fields have different arguments` |
| `{ club(id: "c1") { name: description name } }` | `FieldsConflict : 'club/name' : fields have different nullability shapes` |
| `{ x: club(id: "c1") { name } x: club(id: "c1") { memberCount } }` | Merged: `{"x": {"name": "...", "memberCount": 8}}` |

### A warning for later

Aliases let one request do the same expensive work many times. `08-alias-fanout` in lab 2.8 is 25
fields as text and over 200 objects on the server. Module 10 limits it.

2. Why does `name: description name` fail with "nullability shapes" rather than "different arguments"?

<details><summary>Answers</summary>

1. Valid: `{"a": "Hello from Shelfie!", "b": "Hello from Shelfie!"}`.
2. Both fields have no arguments, but they are different fields (`description: String`, `name: String!`)
   under one key; graphql-java reports the first difference it finds, here the type's nullability.
</details>
