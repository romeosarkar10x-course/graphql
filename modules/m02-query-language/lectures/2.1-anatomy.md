# 2.1 Anatomy of a query

## Hook (2 min)

A teammate removed one field from a query to "tidy up". No test failed, no exception was thrown, and a
week later the club card showed `(@null)` in production. By the end of this lecture you will know
exactly why Java said nothing.

## Concept (12 min)

### The parts of an operation

```graphql
query ClubCard($id: ID!) {        # operation type, name, variable definitions
  club(id: $id) {                 # root field with an argument; its { } is a selection set
    name                          # scalar field: a leaf, no { }
    owner {                       # object field: needs its own selection set
      handle
    }
  }
}
```

| Part | Rule |
|---|---|
| Operation type | `query`, `mutation` or `subscription`. A lone anonymous query may drop it: `{ hello }` |
| Operation name | Optional in the grammar, essential in practice: logs, metrics and tooling key on it (lecture 2.7) |
| Selection set | What you want from the object to its left. Every object field must have one; scalars and enums must not |
| Leaf | A scalar (`String`, `Int`, `ID`...) or enum: where a path through the graph ends |

### The response mirrors the request

The `data` object has exactly the keys you selected, nested the same way, in the order you selected
them. Nothing more: a field you did not ask for is not `null`, it is **absent**.

```json
{ "data": { "club": { "name": "The Midnight Readers", "owner": { "handle": "kemia" } } } }
```

### The envelope

| Key | When it appears |
|---|---|
| `data` | The result of execution. Absent if the request failed before executing (syntax or validation error); `null` or partial if a field error bubbled up |
| `errors` | Only when something went wrong; may sit beside `data` |
| `extensions` | Optional map for implementation extras: tracing, query cost, rate limits |

## Java build (20 min)

Lab 2.1: write one record per selection set and let Jackson map the response onto them.

```java
record GraphQlResponse(Data data, List<GraphQlError> errors, Map<String, Object> extensions) {}
record Data(Club club) {}
record Club(String name, String visibility, int memberCount, Owner owner, Book currentBook) {}
record Owner(String name, String handle) {}
```

The records *are* the query, written a second time. Module 13 generates them from the `.graphql` file
so the two can never drift.

## Experiment (15 min)

Measured with Jackson 3.1.8 (probe in `_workbench/2026-11-21-m02-probe/jackson/`):

| Change | What happens | Why |
|---|---|---|
| Remove `handle` from the query | Card prints `(@null)`, no error | Absent key: a `String` component stays null |
| Remove `memberCount` from the query | `MismatchedInputException: Cannot map null into type int` | Jackson 3 enables `FAIL_ON_NULL_FOR_PRIMITIVES` by default |
| Add `description` to the query only | Nothing | Jackson 3 disables `FAIL_ON_UNKNOWN_PROPERTIES` by default |

Run all three yourself and explain them in `notes.md`.

## Check (3 min)

1. You select `club(id: "c1") { owner }`. What comes back?
2. A response has `errors` and no `data` key. Did any resolver run?

<details><summary>Answers</summary>

1. A validation error, `SubselectionRequired`: `owner` is an object type, so it needs `{ ... }`.
2. No. A missing `data` key means the request failed before execution: parsing or validation.
</details>
