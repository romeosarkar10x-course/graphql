# 2.4 Fragments

## Hook (2 min)

The profile page's query is 70 lines, and the same four user fields appear three times. Someone adds
`pronouns` to two of them and forgets the third. Fragments are how GraphQL documents stop repeating
themselves, and how each UI component declares the data it needs.

## Concept (15 min)

### Named fragments

```graphql
fragment UserCard on User { id name handle avatarUrl }

query { user(id: "u1") { ...UserCard bio } }
```

A fragment is a reusable selection set with a **type condition** (`on User`). Spreading it (`...UserCard`)
pastes its fields in place. Fragments can spread other fragments.

### Inline fragments and type conditions

`search` returns `union SearchResult = Book | Club | User`. A union has no fields of its own (only
`__typename`), so you select per member type:

```graphql
{ search(text: "the") { __typename ... on Book { title } ... on Club { name } } }
```

A result that matches no condition still appears, as `{}` (plus `__typename` if you asked).

### The rules (graphql-java 26.1's messages)

| Rule | Counter-example | Error |
|---|---|---|
| Spread only where the type can match | `club { ...B }` with `fragment B on Book` | `InvalidFragmentType ... 'Club' can never be of type 'Book'` |
| Every fragment must be used | `{ hello } fragment A on Club { name }` | `UnusedFragment` |
| No cycles | A spreads itself via `owner { clubs { ...A } }` | `FragmentCycle@[A]` |

Cycles are invalid even though the data is finite: validation never looks at data, and the text would
expand forever.

### Field order and merging

Fields come back in the order they are **first** selected, and a spread contributes its fields where
it stands. Overlapping fields merge (lecture 2.3). So a refactor can keep the data and still change the
bytes, which matters for snapshot tests and response caches.

### Fragment arguments (RFC #1224, preview)

Today a fragment cannot take parameters: "book tile with the last 3 reviews" and "with the last 10"
need two fragments or a shared operation variable. The RFC proposes `...BookTile(reviews: 3)`.
graphql-java 26.1 does not parse it: `Invalid syntax with offending token '(' at line 1 column 7`.
