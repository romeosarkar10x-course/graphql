# 2.2 Arguments and variables

## Hook (2 min)

A book search built with `String.format` works for weeks. Then someone searches for
`", first: 20) { publishedYear title } __schema { types { name } } } #` and gets every book plus a list
of every type in the schema. The server did nothing wrong.

## Concept (12 min)

### Arguments

Any field can take arguments, not just root fields: `members(first: 3)`, `reviews(last: 5)`. Arguments
are typed in the schema and may have defaults: `books(titleContains: String, first: Int = 20)`.

### Variables

```graphql
query BookSearch($text: String!, $first: Int = 5) {
  books(titleContains: $text, first: $first) { title }
}
```
```json
{ "query": "...", "operationName": "BookSearch", "variables": { "text": "the" } }
```

| Rule | Example |
|---|---|
| Declared in the operation with a type | `$text: String!` |
| `!` means the caller must send a non-null value | `query C($id: ID!)` with `{}`: `Variable 'id' has coerced Null value for NonNull type 'ID!'` |
| A default makes it optional | `$first: Int = 5` |
| Type must fit where it is used | `$id: ID!` passed to `first: Int` gives `VariableTypeMismatch` |
| Every declared variable must be used | `UnusedVariable` |

Messages above are graphql-java 26.1's, captured in `_workbench/2026-11-21-m02-probe/probe-server.txt`.

### Who decides a value

1. The value in `variables`, if the key is present (an explicit `null` counts as present).
2. Otherwise the variable's default (`$first: Int = 5`).
3. Otherwise the argument counts as not given, so the schema's argument default (`first: Int = 20`) applies.

### Why variables exist

- **Safety:** values never become syntax, so input cannot change the document.
- **One constant document:** cacheable parse and validation, persisted queries, allowlists (Modules 9, 10).
- **Typing:** values are coerced against the declared types before execution.

## Check (3 min)

1. `query Q($n: Int = 2) { club(id: "c1") { members(first: $n) { name } } }` with no variables. How many members?
2. Is GraphQL injection a problem if the server has introspection disabled?

<details><summary>Answers</summary>

1. Two: the variable's default applies.
2. Yes. Introspection was just a visible payload; the attacker can still change limits, add fields,
   or multiply expensive selections with aliases.
