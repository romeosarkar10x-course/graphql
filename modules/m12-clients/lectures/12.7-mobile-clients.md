# 12.7 Mobile clients (overview track)

## Hook (2 min)

On a train through a tunnel, the Shelfie app must still show the club, and the review written in the tunnel
must reach the server when the signal comes back. That is a cache that survives restarts, plus an outbox.

## Concept (15 min)

### Apollo Kotlin

The GraphQL client for Android and Kotlin Multiplatform. Codegen is central: the Gradle plugin generates a
Kotlin model per operation from your `.graphql` files and the schema (there is no current Maven plugin; the
community one targets Apollo 3.8). The cache is configured **in the schema**, with client-side extensions:

```graphql
extend type Book @typePolicy(keyFields: "id")
```

Without type policies, records are keyed by their path in the response: the card's book and the mutation's
book are different records, and the measured lab run still showed 4.2 after a successful sync.

### Offline

- **Persistence:** a SQLite normalised cache (`SqlNormalizedCacheFactory`) survives the process; in memory, it
  would not.
- **Fetch policies:** `CacheFirst` (default), `NetworkFirst`, `CacheOnly`, `NetworkOnly`, `CacheAndNetwork`.
  Offline reads are `CacheOnly` or a fallback from `NetworkFirst`.
- **Errors are values:** `execute()` returns a response whose `exception` is an `ApolloNetworkException`; it
  does not throw.
- **Writes while offline** need an outbox the app owns: Apollo's `optimisticUpdates` live in memory and are
  rolled back when the mutation fails, so they do not survive a restart. Replays must be idempotent (lab 12.8).

### What Android adds

The Android Gradle plugin, connectivity callbacks (`ConnectivityManager`) to trigger the sync, and
`WorkManager` to run it in the background with a network constraint. The GraphQL parts are the same code.

## Java build (20 min)

Optional lab 12.7: Apollo Kotlin 5.2 on the JVM with Gradle 9.9 in its own image (`bin/course mobile`), no
Android SDK: each command is a new process, Toxiproxy is the airplane-mode switch.

## Experiment (15 min)

Airplane-mode test: read from cache, queue a mutation, sync when back online, and show the card from the cache
with Shelfie's new average. Then remove the type policies and run it again.

## Check

1. Why does the card read from the cache still show 4.2 after a successful sync without type policies?
2. Why is an optimistic update not an outbox?
3. Where in this lab is the "airplane mode", and what is the real one on a phone?

<details><summary>Answers</summary>

1. Records are keyed by path: the card's `currentBook` and the mutation's `review.book` are two records, so the
   mutation's average went into the second one.
2. It is a temporary layer in memory, removed when the mutation completes or fails; a queued write has to
   survive failures and restarts until the server accepts it.
3. A Toxiproxy proxy that the script disables and enables; on a phone, the OS reports connectivity changes
   (`ConnectivityManager` callbacks) and a background job syncs.

</details>
