# 12.3 Type-safe Java clients

## Hook (2 min)

Someone renames `Book.title` to `Book.name`. Lab 12.2's digest compiles, deploys, and fails on the first
request in production. Could the compiler have told you?

## Concept (15 min)

### Three places to keep the truth about a selection set

| Approach | Source of truth | A rename fails |
|---|---|---|
| document files (12.2) | the `.graphql` file | at runtime, on first call (or in CI, if documents are validated against the schema: Module 13) |
| generated projections (this lecture) | the schema, turned into Java | at compile time |
| derived from Java types (12.4, typesafe) | your records and interfaces | at runtime, as a validation error |

### DGS codegen's client API

`graphqlcodegen-maven-plugin` (the Maven port of Netflix's Gradle-only DGS codegen) with `generateClientApi`
writes, per root field, a `ClubGraphQLQuery` (the field and its arguments, a builder) and a
`ClubProjectionRoot` (the selection set, a fluent chain: `.currentBook().title().reviews(2).rating().root()`),
plus a Java type per schema type. Spring for GraphQL's `DgsGraphQlClient` (2.0) runs them on any
`GraphQlClient`, several root fields per request:

```java
client.request(ClubGraphQLQuery.newRequest().id("c1").build()).projection(clubProjection)
      .request(BooksGraphQLQuery.newRequest().first(3).build()).projection(booksProjection)
      .executeSync();
```

No DGS framework at runtime: only `graphql-dgs-codegen-shared-core`, so Module 6's graphql-java 25 pin for DGS
does not apply.

### What it sends, and what it costs (measured)

The generated document inlines arguments as literals and has no operation name:
`{ club(id: "c1") { name currentBook { title reviews(last: 2) { rating } } } }`. Every id is a different
document text, which defeats a server's parsed-document cache (9.8) and persisted documents (9.6, 10.5);
`...WithVariableReferences` methods put variables back. For the 30-type reference schema the plugin wrote 46
client classes and 27 types. A rename of `Book.title` gave three `cannot find symbol` errors in `ClubPage.java`.

## Java build (20 min)

## Experiment (15 min)

Rename a schema field; watch the client fail to compile, not at runtime. Then print the document that went over
the wire and decide whether you would ship literal arguments to production.

## Check

1. What does a projection's `.parent()` do, and why does the chain need it?
2. Why can literal arguments hurt a server even though the response is identical?
3. Name one thing a document file gives you that generated projections do not.

<details><summary>Answers</summary>

1. A method for an object field returns that field's projection, so the chain moves down; `.parent()` moves
   back up one level (`.root()` to the top) to select a sibling field.
2. The document text changes with every argument value: parsed-document caches miss, APQ stores one hash per
   value, and an allow-list of trusted documents cannot list them.
3. A readable document shared by reviewers, GraphiQL, the server's logs and schema checks in CI; and variables.

</details>
