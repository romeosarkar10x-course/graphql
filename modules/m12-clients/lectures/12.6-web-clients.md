# 12.6 Web clients (overview track)

## Hook (2 min)

A club page with eight member rows. One review changes the book's average. How many components re-render?
With the most common Apollo Client code: ten. With Relay: one. Lab 12.6 measures it.

## Concept (15 min)

### Three clients

| | Apollo Client 4 | urql | Relay |
|---|---|---|---|
| Cache | normalised (`InMemoryCache`) | document cache by default (whole results, invalidated by `__typename`); normalised with Graphcache | normalised store, records keyed by `id` |
| Build step | none | none | `relay-compiler` + Babel plugin, required |
| Fragments | optional; data masking opt-in (`dataMasking: true`, `useFragment`) | optional | required; masking always on |
| Pagination | field policies | Graphcache resolvers | connections (`@connection`, `usePaginationFragment`) |

### Fragment colocation and data masking

Each component declares the fields it reads as a fragment in its own file, and the parent's query spreads
them. With **masking**, the parent cannot read its children's fields at all, and each component subscribes to
its own fragment's data only: a change to `Book.averageRating` re-renders only the component whose fragment
selected it. Without masking, the query's hook at the top re-renders, and React re-renders every child it
returns, unless each is wrapped in `React.memo` and the cache preserves the identity of unchanged objects
(Apollo does).

### Measured (lab 12.6, after one `createReview`)

| Setup | ClubCard | BookPanel | MemberRow (8) |
|---|---|---|---|
| Apollo Client, props | 1 | 1 | 8 |
| Apollo Client, props + `React.memo` | 1 | 1 | 0 |
| Apollo Client 4, data masking | 0 | 1 | 0 |
| Relay | 0 | 1 | 0 |

All four showed the new average with two requests (query and mutation): each normalised cache merged the
mutation's book.

### Costs

Relay's guarantees come from its compiler: fragment names tied to file names, globally unique ids, a build
step. On this setup relay-compiler 20.1.1 panicked on a schema file named `.graphqls`, and Node needed a
resolve hook for Babel's extensionless artifact imports. Apollo with masking gets the same render counts as an
opt-in, with no compiler.

Same screen in Apollo Client and Relay; compare re-render counts after one mutation, and explain each number.

## Check

1. Why does the props version re-render all eight member rows when only the book changed?
2. What does `React.memo` rely on to skip a row?
3. What does Relay ask of the server's ids, and why?

<details><summary>Answers</summary>

1. `useQuery` at the top watches the whole result; it changed, so `ClubCard` re-renders and React re-renders
   every child element it returns.
2. Props that are `===` to the previous render's. Apollo keeps unchanged objects identical between results,
   so the rows' `user` objects are the same objects.
3. Ids unique across all types: Relay's store keys records by `id` alone (Shelfie's `b1`, `c1`, `u1` happen to
   be). The Global Object Identification convention (lecture 7.2) exists for this.

</details>
