# Hints, demo day

1. Write the script as what the audience sees each minute, not what you will say: if a minute has nothing on
   screen that changes, it is a slide, and it can go.
2. Rehearse from a stopped stack: the first demo failure is almost always start-up (a port in use, a stale jar,
   Tempo search lag). Keep the commands in the script, and open traces by id.
3. For the questions, reread your ADRs' Consequences sections: most good questions are about a consequence you
   wrote down, and the best answer starts with the trade-off, not the defence.
