# 8.6 Partial results on purpose

## Hook (2 min)

The reviews service is down. Should the club page be empty, or should it show the club with a note
"reviews unavailable"? The second, obviously. With `recentReviews: [Review!]!` and a throwing fetcher
you get the first.

## Concept (15 min)

### `DataFetcherResult`

A graphql-java fetcher may return `DataFetcherResult.newResult().data(x).errors(...).localContext(c)`
instead of a plain value:

- **data and errors together.** The reviews service is down: return `List.of()` *and* an error with
  `extensions.code: REVIEWS_UNAVAILABLE` at the field's own path. The non-null list survives, the club
  renders, and the client knows why the list is empty. The batch answered for 3 of 5: return the 3
  and **one** error listing the missing ids. Error paths should be unique
  ([#1183](https://rfcs.graphql.org/rfcs/1183/)).
- **localContext.** A value for the fetchers *below* this field only. `members` passes the club down,
  so `Member.isOwner` compares against `club.ownerId()` instead of loading the club again. Lab 8.7's
  starter loaded it 10 times for one page; the solution loads it once. Unlike `GraphQLContext`, it is
  scoped to the subtree. Set it in every parent whose children need it (`members` and `recentReviews`).

### Is that allowed?

The spec says a field error makes the field `null`. A value *and* an error at the same path is a
graphql-java convention, not something the spec describes. Clients that look only at `data` see an
empty list and no reason. Clients that read `errors` by path can show "reviews unavailable". Document it in the error
contract. Lecture 8.7's `onError: NULL` keeps the spec's semantics ("null plus an error") without
nulling the parent, and is the standard way to get there.

### Catch narrowly

Catch the dependency's own exception (`ReviewsUnavailableException`) around the one call. A blanket
`catch (Exception)` turns your own bugs into "reviews are unavailable".

`bin/course java ClubPage.java DOWN` before and after: from `data: {club: null}` to the page with an

## Check (3 min)

1. Why return an empty list rather than make `recentReviews` nullable?
2. Why doesn't `GraphQLContext` work as well as `localContext` for the club?

<details><summary>Answers</summary>

1. A nullable list would also do it, but then every client handles `null` and `[]`, which mean the same
   thing here. The error says why it is empty. Both are honest; the empty list is cheaper for clients.
2. `GraphQLContext` is one map for the whole request: a query with two clubs (aliases) would have two
   writers for one key. `localContext` belongs to the subtree, so each club's members see their own club.
</details>
