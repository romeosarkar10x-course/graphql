# 8.3 Filtering, sorting, search

## Hook (2 min)

`books(where: {field: "title", op: "LIKE", value: "%a%"})` looks flexible. It is also a promise to make
every column, every operator and every combination fast, safe and supported forever.

## Concept (15 min)

### Named filters, not a query language

A filter input names exactly what clients may ask: `BookFilter { genres, publishedFrom, publishedTo,
minRating, author, search }`. Each field has an index or a cheap check behind it, a description, and
can be deprecated on its own. Rules worth writing into the schema's descriptions:

- **null vs empty.** `genres: null` means "don't filter". `genres: []` means "no genre", so it matches
  nothing. Treating `[]` as "any" turns a user's empty selection into the whole catalogue.
- **Invalid combinations are errors**: `publishedFrom` after `publishedTo`, `RELEVANCE` without a search.
- Even named filters can't all be indexed together. On 1,000,000 rows, a genre-and-decade filter sorted by title
  took 75.7 ms, because PostgreSQL walked the title index and filtered.

### Sort enums and the tie-breaker

`orderBy: {field: TITLE, direction: ASC}` with an enum, never a free-form string. Always append a
unique key: the catalogue has 460 titles for 10,000 books. Lab 8.4's mutation run removed the `id`
tie-breaker, and the property test failed on its second try, shrunk to "no filter, `TITLE DESC`".
Ascending ties had happened to come back in id order.

### totalCount is a second query

`count(*)` over every match: 30 ms unfiltered at a million rows. Run it only when `totalCount` is
selected (`DataFetchingFieldSelectionSet.contains`), cap it (`1,000+`), estimate it, or drop it.

### Full-text search in PostgreSQL

`to_tsvector('english', title || ' ' || blurb) @@ websearch_to_tsquery('english', q)` with a GIN index
on the same expression, ranked with `ts_rank`. `websearch_to_tsquery` takes what users type: words,
`"quoted phrases"`, `-excluded`, `or`.

### Specifications, and one Hibernate trap

One JPA `Specification` per field, combined with `Specification.allOf(list)`. Spring Data 4 rejects
`spec.and(null)`. Inside `cb.function(...)`, `cb.literal(search)` puts the text into the SQL itself:
Hibernate 7.4 escapes the quotes, but every search becomes a new statement, and
`hibernate.criteria.value_handling_mode=bind` doesn't change it. `HibernateCriteriaBuilder.value(search)`
binds it as `?`.

## Experiment (15 min)

Property-based testing finds the bugs nobody writes an example for. Lab 8.4's three mutations were
caught on tries 2, 3 and 9: tie order, `[]` as "any", and an exclusive `publishedTo` (shrunk to
1890..1900, the first year with books). The metamorphic property, "a narrower filter never grows the
result", caught none of the three, and caught a bug in the test itself instead.

## Check (3 min)

1. Why is `orderBy: String` worse than an enum, even if you validate the string?
2. Why did the starter pass the default-order Hurl example and still fail the oracle?

<details><summary>Answers</summary>

1. The enum is in the schema: clients see the allowed values, tools validate them, and deprecating one
   is a schema change. A validated string hides all of that and invites injection into `ORDER BY`.
2. PostgreSQL returned title ties in physical order, which is id order, for that one ascending case.
   The oracle tried 300 cases, including descending sorts and other keys, where ties come back in
   another order.
</details>
