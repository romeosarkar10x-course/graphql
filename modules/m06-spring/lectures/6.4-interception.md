# 6.4 Interception and customisation

## Hook (2 min)

`Meetup.startsAtLocal` is three levels below the root and needs one HTTP header. Nothing in between should
have to pass it along.

## Concept (15 min)

| Extension point | Use |
|---|---|
| `WebGraphQlInterceptor` | HTTP request → `ExecutionInput` (headers into `GraphQLContext`), and response → headers, extensions |
| `RuntimeWiringConfigurer` | plain graphql-java wiring: scalars, directives, type resolvers |
| `GraphQlSourceBuilderCustomizer` | the `GraphQlSource` builder: instrumentation, exception resolvers, inspection, type visitors |

Found while building lab 6.4: a fetcher wrapper for an `@uppercase` directive saw a
`reactor.core.publisher.Mono`, not the `String`, because Spring's controller fetchers return reactive
values that Spring adapts later. Plain graphql-java code inside Spring must map inside the `Mono`
(probe: `_workbench/2026-11-21-m05-probe/spring-directive-wiring.txt`).

## Java build (20 min)

Lab 6.4: a tenant header into GraphQLContext and back out as a header and `extensions.tenant`; `@uppercase`
wired with a type visitor.

## Experiment (15 min)

Same query, three tenants; read `startsAtLocal` change.

## Check (3 min)

1. Where does the interceptor put a request-wide value so a nested fetcher can read it?
2. Why can a wrapper's `value instanceof String` fail on a String field in Spring?

<details><summary>Answers</summary>

1. In the ExecutionInput's `GraphQLContext` (`configureExecutionInput`), read with `@ContextValue`.
2. The fetcher returns a `Mono<String>`; the wrapper must map inside it.
</details>
