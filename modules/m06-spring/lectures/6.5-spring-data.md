# 6.5 Spring Data integration

## Hook (2 min)

`@GraphQlRepository` on one interface, and `book(id:)` and `books(author:, publishedYear:)` work with no
fetcher code at all. The question is what you gave away.

## Concept (15 min)

A repository that is also a `QueryByExampleExecutor<Book>` (or `QuerydslPredicateExecutor<Book>`) and is
annotated `@GraphQlRepository` gets registered for every Query field that returns `Book` or `[Book]` and
has no other fetcher. Arguments bind by name onto an example entity: exact matches, ANDed.

SQL emitted in lab 6.5 (`_workbench/2026-11-21-m05-probe/spring-data-sql.txt`):

| Field | SQL |
|---|---|
| `book(id:)`, generated | `select` all five columns `... where b1_0.id=? fetch first ? rows only` |
| `books(author:, publishedYear:)`, generated | `... where b1_0.published_year=? and b1_0.author=?` |
| `searchBooks(titleContains:)`, hand-written derived query | `... where upper(b1_0.title) like upper(?) ... order by b1_0.published_year` |

Every query reads every column, whatever the client selected. Generated fetchers cannot say "contains",
ranges, sorting or joins, and they tie the public schema to entity property names.

Querydsl works the same way but needs an annotation processor; the original `com.querydsl` line has had no
release since 2024 (fork: `io.github.openfeign.querydsl`). `@ProjectedPayload` interfaces bind arguments
onto Spring Data projections.

## Check (3 min)

1. How does Spring decide which Query fields a `@GraphQlRepository` serves?
2. Name one query Query by Example cannot express.

<details><summary>Answers</summary>

1. By return type: the GraphQL type name matches the repository's domain type (`Book`), and the field
   has no other fetcher.
2. Any of: contains, ranges, OR, sorting, joins.
