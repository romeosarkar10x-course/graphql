# 6.2 Annotated controllers

## Hook (2 min)

`updateClub(input: {id: "c2"})` and `updateClub(input: {id: "c2", description: null})` bind to the same
Java record. One should keep the description; the other should delete it.

## Concept (15 min)

| Annotation | Binds |
|---|---|
| `@QueryMapping`, `@MutationMapping`, `@SubscriptionMapping` | root fields (method name = field name) |
| `@SchemaMapping(typeName, field)` | any field; first parameter = the parent |
| `@BatchMapping` | a batched field (Module 8) |
| `@Argument` | one argument, converted (records for input types) |
| `@Arguments` | all arguments into one object |
| `ArgumentValue<T>` | an argument or input field that may be omitted, null, or a value |
| `@ContextValue` | a `GraphQLContext` entry (request-wide) |
| `@LocalContextValue` | a local-context entry from the parent's `DataFetcherResult`; the local context must be a `GraphQLContext` |

Projected interfaces (`@ProjectedPayload`) bind arguments onto Spring Data projections; they belong with
6.5.

## Java build (20 min)

Lab 6.2: `roleInClub` from local context, `bookSearch` with `@Arguments`, `updateClub` as a real patch.

## Experiment (15 min)

Send the patch with a field omitted, with `null`, and with a value; watch `ArgumentValue.isOmitted()`.

## Check (3 min)

1. Two controllers map `Club.owner`. When do you find out?
2. What must a parent return for a child's `@LocalContextValue` to work?

<details><summary>Answers</summary>

1. At startup: duplicate mappings fail the context.
2. A `DataFetcherResult` whose `localContext` is a `GraphQLContext`.
</details>
