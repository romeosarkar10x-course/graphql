# 6.6 Exception handling

## Hook (2 min)

Throw six different exceptions from a Spring controller and the client sees six times
`"INTERNAL_ERROR for bba88465-..."`. Safer than graphql-java's default, and just as unhelpful.

## Concept (15 min)

Spring masks every unhandled exception as `INTERNAL_ERROR` with the execution id (logged with the real
exception). Map the ones you mean:

```java
@ControllerAdvice
class ErrorAdvice {
    @GraphQlExceptionHandler
    GraphQLError notFound(Problems.NotFound e, DataFetchingEnvironment env) {
        return GraphqlErrorBuilder.newError(env).errorType(ErrorType.NOT_FOUND).message(e.getMessage()).build();
    }
}
```

`ErrorType`: `BAD_REQUEST`, `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `INTERNAL_ERROR`. Anything finer
(CONFLICT, retryable) goes in `extensions`, or in your own `ErrorClassification`. Lower-level hooks:
`DataFetcherExceptionResolverAdapter` beans. Module 4.3 still applies: expected outcomes of mutations are
payload data, not errors.
