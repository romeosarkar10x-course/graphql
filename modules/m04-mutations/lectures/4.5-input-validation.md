# 4.5 Input validation

## Hook (2 min)

Twelve spaces pass `@Size(min: 10)`. `[String!] @Size(max: 5)` does not limit a list to five tags: it
limits every tag to five characters. Validation has layers, and each layer sees different things.

## Concept (15 min)

### Four layers

| Layer | Checks | Rejected as | Visible to clients |
|---|---|---|---|
| GraphQL itself | types, required, unknown fields, enum values | request error, no execution | yes: the schema |
| Schema directives (graphql-java-extended-validation) | ranges, lengths, patterns, list sizes | field error, `ExtendedValidationError` | in the SDL, **not** in introspection |
| Bean Validation on input records | rules that need code: not blank, cross-field, uniqueness | `userErrors` (you map them) | no |
| Business rules in the resolver | facts about the world: exists, allowed, not a duplicate | `userErrors` | no |

Rule of thumb: the earlier a rule can run, the earlier it should, as long as the client can
understand the error.

### graphql-java-extended-validation

Declare the directives in the SDL (`@Range`, `@Size`, `@Pattern`, `@ContainerSize`...), wire
`ValidationSchemaWiring`. On graphql-java 26.1 the course uses version 24.0 with Hibernate Validator 8:
with Hibernate Validator 9 it fails with `NoSuchMethodError` on the first violation
(`_workbench/2026-11-21-m03-probe/ext-validation-compat.txt`). On lists, `@Size` applies to each element;
`@ContainerSize` to the list.

### Jakarta Bean Validation

Annotations on record components (`@NotBlank`), methods (`@AssertTrue boolean isTagsUnique()`), run
with `Validator.validate(record)`. Spring for GraphQL runs it for `@Argument @Valid` (Module 6).

### Error shapes

Directive violations are top-level errors with `extensions.classification.validatedPath`; Bean and
business violations are `userErrors` with `field`. A form wants the second. Map one to the other, or
document both.
