# 4.3 Errors as data

## Hook (2 min)

A user types a 5-character review. The server answers with HTTP 200, `data: {createReview: null}` and
an `errors` entry whose message is "Body must be 10 to 2000 characters". The app shows "Something went
wrong". The rule the user broke was data; the response made it a crash.

## Concept (15 min)

### Two kinds of error

| | Top-level `errors` | Domain errors |
|---|---|---|
| Examples | syntax, unknown field, wrong variable type, a resolver bug, the database down | rating out of range, already reviewed, not allowed |
| For | the developer | the user |
| Shape | defined by the spec: `message`, `locations`, `path`, `extensions` | defined by **your schema** |
| Typed, in introspection, in codegen | no | yes |

### Style 1: payload with `userErrors`

```graphql
type CreateReviewPayload { review: Review  userErrors: [UserError!]! }
type UserError { field: [String!]  message: String!  code: UserErrorCode! }
```

Shopify's convention. Simple; one shape for every mutation; `field` points at the input. Risk: a client
that never selects `userErrors` reads `review: null` as success (lab 4.3's starter).

### Style 2: result union

```graphql
union CreateReviewResult = ReviewCreated | ValidationFailed | NotAllowed
```

The outcome is a type; clients branch on `__typename`. Each outcome carries exactly its data. Cost: a
type per outcome, and adding one is a union change old clients must survive (3.7).

### Java side: one sealed type

Map either style to `sealed interface CreateReviewResult permits ReviewCreated, ValidationFailed,
NotAllowed` and handle it with an exhaustive `switch`. The UI code never knows which wire style was used.

## Java build (20 min)

Lab 4.3: `ReviewClient` calls both reference mutations for four cases and maps both into the same
sealed records; both styles must print the same outcomes.

## Experiment (15 min)

Consume both styles from a Java client; count lines of handling code; decide which mistakes each style
makes silent.

## Check (3 min)

1. A client sends `rating: "five"`. Top-level error or domain error?
2. What must a union-style client always select?

<details><summary>Answers</summary>

1. Top-level: it fails validation (or variable coercion) before any resolver runs.
2. `__typename`, plus a fallback branch for members it does not know.
</details>
