# 9.1 Seeing N+1

## Hook (2 min)

Every resolver in lab 9.1's starter is one line and uses an index. The club dashboard still takes
1,250 SQL statements. Nobody wrote a slow query. The schema multiplied the fast ones.

## Concept (15 min)

### Where the statements come from

graphql-java resolves a field once per parent. A resolver that loads its own data runs once per parent
too, so every list multiplies the statements below it. For the dashboard (`contract/dashboard.graphql`):

| Field | Parents | Statements |
|---|---|---|
| `clubs(first: 10)` | 1 | 1 |
| `owner`, `ownerPicks`, `memberCount`, `members` | 10 clubs | 4 x 10 |
| `currentBook` | 10 clubs, 1 without a book | 9 |
| `reviews(first: 5)` | 200 members | 200 |
| `book` | 1,000 reviews | 1,000 |
| | | **1,250** |

The deepest field dominates: 1,000 of the 1,250 come from `Review.book`. Nesting compounds it: with
fan-outs f1, f2, f3, one field per level costs 1 + f1 + f1·f2 + f1·f2·f3.

### Why it hurts

Each statement is a round trip. On the course machine the dashboard took about 200 ms warm (`_workbench/2026-11-21-m09-probe/naive-vs-batch.txt`),
about 0.16 ms per statement to a local database. Put the database 1 ms away and the same page takes
more than a second, with the same SQL.

### Seeing it

- **Hibernate's log** (`spring.jpa.show-sql`) prints every statement. That's good for reading and too
  noisy to assert on.
- **A counter**: datasource-proxy wraps the `DataSource` and calls a listener around every statement.
  A `BeanPostProcessor` swaps the wrapped one in; a `WebGraphQlInterceptor` reports the per-request
  count in `extensions.sql.statements`. Now a test can assert on the number.

## Check (3 min)

1. `{ clubs(first: 10) { currentBook { title } } }` on the naive app: 11 statements?
2. Why is the counter global, and when is its per-request number wrong?

<details><summary>Answers</summary>

1. 10: club 10 has no current book, and the resolver returns null without a query.
2. Loaders run on other threads, so a per-thread counter would miss their statements. A global counter
   only gives exact per-request numbers while requests run one at a time, as in tests and in this lab.
</details>
