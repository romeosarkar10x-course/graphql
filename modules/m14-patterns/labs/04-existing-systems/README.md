# Lab 14.4: GraphQL over existing systems

Lecture: [14.4 GraphQL over existing systems](../../lectures/14.4-existing-systems.md). Grading: auto + rubric.
Needs the reference server (`bin/course ref up`).

A backend-for-frontend: the book page is one GraphQL query; behind it are three systems Shelfie did not build in
GraphQL.

| Field | Source | Client |
|---|---|---|
| `book(id:)`: title, authors, isbn, year | the catalogue's REST API, `shelfie-ref:8080/api/books/{id}` | `RestClient` (provided) |
| `Book.reviews`, `Review.author` | the reviews gRPC service, `shelfie-ref:9090` (`shelfie.v1.ShelfieService`) | grpc-java stubs, generated by the pom from `src/main/proto/shelfie.proto` |
| `Book.openLibrary` | Open Library's Books API (someone else's, on the internet) | `RestClient` with Resilience4j 2.4.0 |

Write the gRPC client, then make Open Library's bad days cost one field, not the page: when it is slow, down,
or answering an HTML page with 200, `openLibrary` is null with an error whose `extensions.code` is
`UPSTREAM_UNAVAILABLE`, and the page answers within 1.5 s. While it stays down, stop calling it (a circuit
breaker). Identify yourself with a `User-Agent` that names Shelfie (Open Library asks API users to).

The test points `shelfie.openlibrary-url` at a **fake Open Library** ([contract/openlibrary](../../contract/openlibrary/))
that serves responses recorded from the real API on 2026-11-22 and can be switched to slow, down, garbage or
rate-limited. Try your BFF against the real one too: `java -jar target/shelfie-bff.jar` (the default URL).

```bash
bin/course start m14/04
cd workspace/m14-patterns/04-existing-systems
bin/course shell -c 'mvn -q package && java -jar target/shelfie-bff.jar'
bin/course test m14/04
```

The experiment (syllabus: "kill it and keep the page working") is the grader's F01 to F05: hang, garbage, down,
twenty pages while down, recovery.

In `notes.md`: one page over three systems, the bad days with the grader's numbers, and what a BFF owns.
