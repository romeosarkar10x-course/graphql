# REST or GraphQL? — 20 scenario cards

Styles allowed: **REST**, **GraphQL**, **gRPC**, **tRPC**, **OData**, **webhook**, **"none: plain file / CDN"**.
For each card: a pick and the one trade-off that decided it.

1. A weather widget embedded on 40,000 third-party blogs, same data for every visitor in a city.
2. An Android app showing a feed that mixes posts, ads, event invites and friend suggestions.
3. A payments provider notifying merchants that a charge succeeded.
4. A machine-learning feature store serving 200,000 lookups per second to other backend services.
5. A ten-year-old monolith's admin screens, one internal team, simple CRUD forms.
6. A smart-TV app whose release cycle is 6 months; the home screen layout changes monthly.
7. A public open-data portal of government spending, used from Excel by journalists.
8. A startup's Next.js app with a TypeScript backend and one developer.
9. An e-commerce product page combining catalogue, pricing, inventory, reviews and recommendations owned by 5 teams.
10. Downloading a 2 GB nightly database export.
11. A chat feature: messages must appear in other users' open apps within a second.
12. A partner API where each partner may only see some fields, and partners keep asking for "just one more field".
13. Streaming telemetry from 10,000 IoT devices on a factory floor to an internal collector.
14. A banking app's "account overview": balances, last 5 transactions, card status, offers.
15. A static marketing site's list of 12 office locations, changed twice a year.
16. Several mobile app versions in the wild, some 2 years old, all hitting the same backend.
17. A developer platform that wants to generate SDKs in 8 languages from one contract.
18. A health check endpoint polled by a load balancer every 2 seconds.
19. A BFF (backend for frontend) for one web app that composes 3 internal REST services.
20. An internal analytics team writing ad-hoc questions against many related entities, changing daily.
