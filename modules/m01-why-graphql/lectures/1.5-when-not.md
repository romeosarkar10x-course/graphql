# 1.5 When not to use it, and who does

## Hook (2 min)

GitHub's 2016 announcement opens by praising its own REST API: inspiration for other companies, cited by
countless tutorials. Then it explains why that was not enough. The best case for GraphQL starts by
taking REST seriously.

## Concept (12 min)

### When not to use GraphQL

| Situation | Why GraphQL is the wrong tool | Use instead |
|---|---|---|
| Simple CRUD, one client, one team | You pay for a schema, a runtime and resolvers and get nothing back | REST, or what you have |
| Files: uploads, downloads, exports | JSON is the wrong envelope for bytes; multipart uploads have CSRF pitfalls (Module 4.6) | Pre-signed URLs to object storage; plain HTTP downloads |
| Cache-heavy public reads | URL-keyed caching in browsers and CDNs is free with GET | REST behind a CDN (or GraphQL with persisted GET queries, Module 9.6, at extra cost) |
| Pushing to systems not connected to you | Subscriptions need a live connection | Webhooks |
| Health checks, OAuth redirects, infrastructure endpoints | Load balancers and identity providers speak plain HTTP | Plain endpoints |
| Untrusted public callers, and no budget for demand control | Any client can send an expensive query | REST, or GraphQL with cost limits from day one (Module 10) |

### Who chose it, and why

Short versions; full table in `plan/company-case-studies.md`.

| Company | The pain | How they run it |
|---|---|---|
| **GitHub** (2016) | REST made "over 60% of the requests made to our database tier"; integrators needed "two or three separate calls"; they wanted OAuth scopes, pagination and type-safety per field, generated docs and clients | One public GraphQL API (v4) beside REST (v3), with cost-based rate limits |
| **Shopify** | Huge Admin API surface; apps over-fetching | GraphQL primary; REST Admin marked legacy (2024); dated API versions and cost budgets |
| **Netflix** | One Studio API owned by many teams | Federated graph on graphql-java and DGS (Java, Spring) |
| **Airbnb** | Duplicated logic across microservices | Viaduct: one central graph that hosts business logic (JVM) |

Notice what the stories share: each started from a measured pain, not from "GraphQL everywhere", and each
kept REST where REST was better.
