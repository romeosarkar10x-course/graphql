# 1.2 The pain it targets

## Hook (2 min)

PayPal's engineering team wrote that in Checkout, each extra round trip cost around 700 ms at the 99th
percentile ([PayPal Engineering](https://medium.com/paypal-engineering/3482f724fb53); figure as quoted in
this course's plan, not re-verified: the post is behind a bot wall). Whatever the exact number, on a
mobile network a round trip is the most expensive thing a screen does. Today you will measure how many a
REST screen needs.

## Concept (15 min)

Six pains, each with the Shelfie club page as the example:

| Pain | What it means | On the club page |
|---|---|---|
| **Under-fetching** | One response is not enough for one screen | The club has `memberIds`, not member names: 5 more calls |
| **Round-trip waterfalls** | Calls that depend on earlier answers must wait | Reviewer names need the reviews first: 3 sequential waves minimum |
| **Over-fetching** | Responses carry fields the screen never shows | Users come with preferences, stats, avatar URLs; about 85% of bytes unused |
| **Endpoint sprawl** | Fixing the above with custom endpoints (`/club-page`, `/club-card`, `/club-page-v2`) | The gRPC `GetClubPage` RPC in the reference server is exactly this |
| **Versioning churn** | Changing a response breaks old clients, so you add `/v2` | Apps two years old still call your API (Meta reported about 1,000 shipped app versions to support by 2015) |
| **Mobile networks** | High latency, low bandwidth, flaky links | Turns all of the above from "a bit slow" into "unusable" |

### Waves, not requests

What hurts is not the number of requests but the number of **sequential** round trips. Requests that
depend only on what you already have can go out together:

```
wave 1   club
wave 2   owner, 5 members, book, reviews, meetups     (all need only the club)
wave 3   3 reviewers                                  (need the reviews)
```

So a perfectly parallel REST client pays 3 × RTT; a naive sequential one pays 11 × RTT. A GraphQL client
pays 1 × RTT, and the server resolves the same waves in-process, microseconds apart.

### Toxiproxy

[Toxiproxy](https://github.com/Shopify/toxiproxy) is a TCP proxy that injects network conditions.
`bin/course toxi latency 700` adds 700 ms to every response on `http://toxiproxy:8666`, which forwards
to the reference server.

## Java build (25 min)

Lab 1.2: `RestClubPage.java` builds the page from five REST endpoints, prints it as JSON and reports
`requests=`, `bytes=` and `ms=`. The grader checks your request count against the server's own counter.

## Experiment (15 min)

Run your client with no latency, then at 700 ms. Draw the dependency graph and predict the time before
you run it. Then make your client sequential on purpose and run it again.
