# 1.1 Where GraphQL came from

## Hook (2 min)

In 2012 Facebook's mobile apps were, in Facebook's own words, "thin wrappers around views of our
mobile website". They were slow and crashed a lot. Rewriting them natively hit a strange wall: there
was no data API for News Feed. It "had only been delivered as HTML".
([Facebook Engineering, 2015](https://engineering.fb.com/2015/09/14/web/graphql-a-data-query-language/))

## Concept (12 min)

### The problem as Facebook described it

They tried their existing options, RESTful resources and FQL (a SQL-like API), and were "frustrated with
the differences between the data we wanted to use in our apps and the server queries they required. We
don't think of data in terms of resource URLs, secondary keys, or join tables; we think about it in terms
of a graph of objects." There was also "a considerable amount of code to write on both the server to
prepare the data and on the client to parse it."

So GraphQL's design goals came straight from mobile product work:

| Goal | Where you will see it |
|---|---|
| The query mirrors the response's shape | Lecture 1.3, Module 2 |
| Hierarchical: follow relationships in one request instead of round trips | Lab 1.3 |
| Strongly typed, and the schema describes itself | Module 3, introspection 2.6 |
| Driven by what the client needs, not by how the server stores it | Module 7 |

### From internal tool to standard

The milestones in lab 1.1 tell this story in three acts:

1. **Facebook's tool (2012–2015).** Built for the native apps; by 2015 it served "hundreds of billions
   of API calls a day" inside Facebook.
2. **Open specification (2015–2018).** A draft spec plus `graphql-js` as reference implementation
   (2015). GitHub bet its public API on it (2016). Facebook relicensed the spec under the Open Web
   Foundation Agreement and `graphql-js` under MIT (2017), which removed a blocker for companies wary of
   Facebook's earlier patent clause. Spec editions became dated releases (June 2018).
3. **Neutral governance (2018–).** The **GraphQL Foundation** under the Linux Foundation (2018) owns the
   spec. Changes go through RFCs and working groups (Module 17.1). Editions followed in October 2021
   and September 2025, the edition this course targets.

Meanwhile the ecosystem grew around it: Apollo Federation (2019) for many teams sharing one graph,
Netflix open-sourcing DGS (2021), Spring for GraphQL 1.0 (2022), Shopify making GraphQL its primary
Admin API (marking REST legacy in 2024; see the case-studies tab in `plan/`).

### Spec vs implementation

The spec defines a **language** (queries, schemas), **validation** rules, **execution** semantics and the
**response** format. It does not define transport (that is the separate GraphQL-over-HTTP spec), storage,
authentication or performance. graphql-java is one implementation; Spring for GraphQL is a framework on
top of it. When something surprises you, ask: spec, or library? Module 17 makes you able to answer.
