# 1.4 GraphQL vs REST vs gRPC vs tRPC vs OData

## Hook (2 min)

The reference server serves one dataset three ways, and the gRPC version contains a confession: next to
`GetClub`, `GetUser` and `GetBook` sits `GetClubPage`, an RPC that exists only because one screen needed
it. Someone will write `GetClubCard` next month.

## Concept (15 min)

### The five styles

| Style | Contract | Wire | Shape decided by | Sweet spot |
|---|---|---|---|---|
| **REST** | Optional (OpenAPI) | HTTP + JSON, one URL per resource | Server | Public resources, cacheable reads, simple CRUD |
| **gRPC** | Required (`.proto`) | HTTP/2 + Protobuf (binary) | Server | Internal service-to-service, high throughput, streaming |
| **GraphQL** | Required (SDL schema) | HTTP + JSON, one endpoint | **Client** | Many clients and screens over a graph of data, mobile, BFFs |
| **tRPC** | The TypeScript types themselves | HTTP + JSON | Server functions | One TypeScript codebase, client and server together |
| **OData** | Required (EDM metadata) | HTTP + JSON, URL query conventions (`$filter`, `$select`, `$expand`) | Client, via URL options | Enterprise data, BI and spreadsheet tools |

### The criteria that decide

| Criterion | Question to ask | Who tends to win |
|---|---|---|
| **Caching** | Is the same data read by many? | REST (URL = cache key) |
| **Round trips** | Does one screen need many related things? | GraphQL; OData `$expand` |
| **Typing and codegen** | Do clients need generated types? | gRPC, GraphQL, tRPC (inferred) |
| **Streaming** | Server or bidirectional streams? | gRPC; GraphQL subscriptions for UI events |
| **Browser reach** | Called from browsers directly? | REST, GraphQL, tRPC (gRPC needs gRPC-Web) |
| **Team topology** | How many teams and languages on each side? | gRPC/REST for many languages, tRPC for one, GraphQL for many clients over one graph |
| **Public vs private** | Can you control or allowlist callers? | Public pushes you to REST, or GraphQL *with* cost limits |

### Same data, three files

| | Get club c1's name |
|---|---|
| REST | `curl localhost:8080/api/clubs/c1` |
| gRPC | `grpcurl -plaintext -d '{"id":"c1"}' shelfie-ref:9090 shelfie.v1.ShelfieService/GetClub` |
| GraphQL | `POST /graphql {"query":"{ club(id: \"c1\") { name } }"}` |
