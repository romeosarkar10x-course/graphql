# 0.1 Welcome and course map

## Hook (2 min)

A team ships a GraphQL server. Every request returns HTTP 200. Their uptime dashboard is green for a
week while a third of all queries fail validation, because a GraphQL error usually still arrives as
`200 OK` with an `errors` array in the body. Their HTTP-level monitoring was looking at the wrong thing.
By the end of this lecture you will have written a test that would have caught it.

## Concept (10 min)

### What you build: Shelfie

Shelfie is a book-club platform: users, clubs, books, shelves, reviews, meetups and live meetup chat.
It grows with the course. Each feature exists because it forces a GraphQL lesson:

| Shelfie feature | Lesson it forces | Module |
|---|---|---|
| Club page (club, members, book, reviews, reviewers) | Nesting, N+1 queries, DataLoader | 1, 9 |
| Activity feed (reviews, joins, meetups mixed) | Interfaces, unions | 3 |
| Meetup chat | Subscriptions | 11 |
| "All books" | Pagination, `@stream` | 8, 11 |
| Members, moderators, owners | Authorization | 10 |
| Accounts, catalog, reviews, clubs as separate teams | Federation | 15 |

Right now a **reference Shelfie** runs for you (`bin/course ref up`). It serves the same data as REST
(`/api`), GraphQL (`/graphql`) and gRPC (port 9090), so Module 1 can compare them. From Module 5 you
build your own.

### How the course is put together


### Contracts, conformance tests, behaviour specs

Every lab ships three language-neutral things so you could redo it in Go or TypeScript later:

1. **Contract:** `.graphql` schema and operation files.
2. **Conformance tests:** [Hurl](https://hurl.dev) files. A Hurl file is a plain-text HTTP request
   plus assertions on the response. It cannot see your Java classes, so it grades any server.
3. **Behaviour spec:** the lab's README, which describes what must happen, not how.

### How grading works

| Grading | How | Command |
|---|---|---|
| auto | Tests in the lab's `tests/` talk to your work and print pass/fail per check | `bin/course test mNN/NN` |
| rubric | Written or design work. An AI agent grades it against the lab's `rubric.md` | `bin/course grade mNN/NN` prints the prompt |
| both | Both of the above | |

Every lab also has a `HINTS.md` with three escalating hints. Read one, try again, then read the next.

`bin/course check --starters` is the course's own self-test: every reference solution passes and
every untouched starter fails. Run it now to see a wall of red: that red is your to-do list.

## Experiment (10 min)

Lab 0.1: run one Hurl file against the reference server and against nothing. A **contract failure**
(the server answered, but not as promised) and a **transport failure** (nobody answered) look different
and are debugged differently. Learn to tell them apart at a glance now; you will see both hundreds of times.

## Check (3 min)

Predict, then check in GraphiQL (http://localhost:8080/graphiql):

1. `{ hello }` returns which HTTP status code? And `{ nope }`?
2. A Hurl test asserts only `HTTP 200`. Name a broken server it would wrongly pass.

<details><summary>Answers</summary>

1. Both 200 with the default `application/json` response type. `{ nope }` carries an `errors` array
   and no `data`. (With `Accept: application/graphql-response+json` the invalid one gets 400; lecture 0.4.)
2. Any server that answers every request with `200` and `{"errors":[...]}`, which is every GraphQL
   server for every invalid query.
</details>
