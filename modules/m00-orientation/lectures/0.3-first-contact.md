# 0.3 First contact

## Hook (2 min)

GitHub's public GraphQL schema is about 76,000 lines of SDL. Nobody reads it. Yet people write
correct queries against it on day one, because a GraphQL API describes itself: the explorer knows
every type, field and argument before you type them. That is what you are about to use.

## Concept (12 min)

### One endpoint

A REST API has many URLs (`/films/1`, `/films/1/characters`, ...). A GraphQL API has **one**,
usually `/graphql`, and every request says *what* it wants in a query document:

```graphql
query FirstFilm {
  film(id: "ZmlsbXM6MQ==") {   # a field with an argument
    title                     # scalar fields: leaves of the tree
    director
  }
}
```

The response mirrors the request's shape:

```json
{ "data": { "film": { "title": "A New Hope", "director": "George Lucas" } } }
```

### The explorer and the docs pane

Explorers (GraphiQL, Altair, GitHub's explorer) send an **introspection query** when they load:
a standard query, part of the spec, that asks the server to describe its own schema. From the answer
they build:

- **autocomplete**: press Ctrl+Space inside `{ }` to list fields valid at that position
- **the docs pane**: every type, its fields, their arguments and types, and their descriptions
- **live validation**: red squiggles before you send anything

Reading types in the docs pane:

| Shown | Means |
|---|---|
| `title: String` | may be null |
| `title: String!` | never null |
| `authors: [String!]!` | a non-null list of non-null strings |
| `country(code: ID!): Country` | the argument `code` is required; the result may be null (not found) |

Module 2.6 takes introspection apart; Module 10.5 asks whether production servers should allow it.

## Check (3 min)

1. `film(id: ID): Film` vs `film(id: ID!): Film!`. What changes for a client?
2. Why does the explorer know about a field you have never heard of?

<details><summary>Answers</summary>

1. With `ID!` the argument is required (omitting it is a validation error). With `Film!` the server
   promises never to return null there; if it cannot produce a film, the error propagates to the
   nearest nullable parent (Module 3.4).
2. It ran an introspection query against the live schema on load.
</details>
