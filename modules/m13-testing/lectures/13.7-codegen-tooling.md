# 13.7 Code generation and dev tooling

## Hook (2 min)

Rename `averageRating` to `avgRating` in the schema. The app compiles, starts, logs one INFO line, and answers
`avgRating: null` to every client (probed). Make the same rename fail the build at the line that needs fixing.

## Concept (15 min)

### Schema-to-types on the server

Schema-first servers write the schema, then code that must agree with it. Code generation makes the agreement
checked: DGS codegen (Maven: `graphqlcodegen-maven-plugin` 3.11.0, a community plugin, because Netflix's own is
Gradle-only) writes a Java class per type and input and a `DgsConstants` class with every type, field and
argument name into `target/generated-sources`. Spring controllers that name fields through it
(`@SchemaMapping(typeName = BOOK.TYPE_NAME, field = BOOK.AverageRating)`,
`@Argument(BOOK.REVIEWS_INPUT_ARGUMENT.Last)`) stop compiling when the schema renames them. Generate inputs and
names freely; generating outputs couples your domain to the schema's shape (every record copied into a generated
class). Spring's own net is schema inspection at start-up: it logs `Unmapped fields: {Book=[avgRating]}`, but
only logs.

### Client projections

The same codegen writes typed client projections (lab 12.3, `DgsGraphQlClient`): a rename on the server fails
the client's build too, if the client regenerates from the published schema.

### IDE support: one config

`graphql.config.yml` says where the schema and the operations are, once, for every tool: graphql-config (the
library behind graphql-eslint and the VS Code GraphQL extension) and the IntelliJ GraphQL plugin, which gives
completion, go-to-definition and validation as you type in `.graphql` files and in strings. The `endpoints`
extension lets the IDE run operations and re-introspect a running server.

### Docs sites

SpectaQL (3.0.9) and Magidoc build static documentation from a schema file or introspection. Probed: SpectaQL
built a 110 KB single `index.html` for Shelfie in about a second, one section per type and per root field, the
descriptions as text: docs are only as good as the descriptions (lab 13.6's `require-description`). GraphQL
Voyager draws the type graph instead (the reference server's `/voyager.html`, Module 3). We pin SpectaQL; Magidoc
9.0.0 was twelve days old when this module was written.

## Experiment (15 min)

Publish a browsable docs site for the Shelfie schema: `bin/course node npm run docs`, then open

## Check

1. Why does `@SchemaMapping public Double averageRating(Book book)` survive a rename and the DgsConstants version
   not?
2. What do you lose by generating output types?
3. Which tools read `graphql.config.yml`?

<details><summary>Answers</summary>

1. The first maps by method name, a string the compiler does not check against the schema; the second refers to a
   generated constant that disappears when the schema field does.
2. Freedom in the domain model: every fetch copies a record into a generated class, and the domain's shape
   follows the schema's.
3. The IntelliJ GraphQL plugin, the VS Code GraphQL extension and graphql-eslint (through graphql-config), and any
   script that loads graphql-config, like the lab's check.

</details>
