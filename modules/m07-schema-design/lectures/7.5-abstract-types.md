# 7.5 Choosing abstract types

## Hook (2 min)

A club's activity feed: a review was posted, a member joined, a meetup was scheduled. Next year: a book
was finished, a poll opened. The choice you make today decides what a phone that never updates shows
for next year's kinds.

## Concept (15 min)

### Three ways to model "one of several kinds"

| | Interface | Union | Enum discriminator |
|---|---|---|---|
| SDL | `interface FeedItem { id happenedAt actor }` + `implements` | `union FeedItem = A \| B \| C` | one `type FeedItem { kind: FeedItemKind! ... }` |
| Shared fields | on the interface, selectable without fragments | none: every field inside `... on` | all on one type |
| Kind-specific fields | on each type, non-null where true | on each type | all on one type, **nullable**, tied to `kind` only by descriptions |
| New kind | new implementing type | new member | new enum value + nullable fields |
| SchemaDiff | SAFE (a type was added) | DANGEROUS (union member added) | DANGEROUS (enum value added) |
| An old client meets the new kind | renders the shared fields | gets `{"__typename": "BookFinished"}` | gets an unknown `kind` |

(Verdicts from graphql-java 26.1 and graphql-inspector 7.0.2 on lab 7.5's schemas, 2026-11-21.)

### Picking

- **Interface** when the kinds share behaviour a client can render generically (who, when), and new
  kinds are the expected change. Feeds, notifications, timeline events.
- **Union** when the members share nothing meaningful (`SearchResult = Book | Club`): a client must know
  each member to show anything, and the schema says so honestly.
- **Enum discriminator** when variants differ in a field or two, clients mostly filter by kind, or a
  single table backs it. The schema can't express "review is set when kind is REVIEW_POSTED".

### Future-proof clients

Whatever the server picks, clients survive new kinds only if they select `__typename` and the shared
fields outside fragments, and treat an unknown type or enum value as "show the generic row", never as an
exception. A `switch` with no `default` is a crash scheduled for the next release.

## Java build (20 min)

Lab 7.5: implement all three for the feed, with a client each; then add `BookFinished` to each and keep
the old clients valid.

## Experiment (15 min)

Add the fourth variant to each design and count client changes. The surprise: the line counts are equal
(one each). The difference is what happens to the clients that don't change.

## Check (3 min)

1. Why can't a union client select `happenedAt` directly on `FeedItem`?
2. SchemaDiff calls the new interface implementation SAFE. Can it still break a client?

<details><summary>Answers</summary>

1. A union has no fields of its own; only `__typename` is selectable on it. The shared fields exist only
   on the member types.
2. Yes: a client that maps `__typename` exhaustively throws on `BookFinished`. SAFE means every document
   stays valid, not that every client handles new data.
</details>
