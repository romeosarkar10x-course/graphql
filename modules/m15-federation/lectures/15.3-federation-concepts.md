# 15.3 Federation concepts

## Hook (2 min)

Delete one line, `@key(fields: "id")` on catalog's `Book`, and composition refuses the whole graph with
`INVALID_FIELD_SHARING: Non-shareable field "Book.id" is resolved from multiple subgraphs`. That line was the
contract between three teams.

## Concept (15 min)

### Entities and keys

An **entity** is a type several subgraphs contribute to, identified by `@key(fields: "id")`. Any subgraph that
declares the type with the same key can add fields; the router fetches them through
`_entities(representations: [{ __typename: "Book", id: "b1" }])`. Several keys (`@key(fields: "id") @key(fields:
"isbn")`) let others point by either. `resolvable: false` declares a key-only stub a subgraph cannot resolve.

### The directives (Federation 2, `@link(url: ".../federation/v2.9", import: [...])`)

| Directive | Problem it solves |
|---|---|
| `@key` | point at and extend another team's type |
| `@shareable` | two subgraphs may both resolve a field (value types, `handle`) |
| `@external` | mention a field you do not resolve, to use it |
| `@provides(fields:)` | "on this path I return these external fields too": saves a step |
| `@requires(fields:)` | compute a field from another subgraph's fields: adds a step |
| `@override(from:, label:)` | move a field; with `label: "percent(25)"`, gradually (progressive override) |
| `@inaccessible` | in the supergraph, never in the API |
| `@tag(name:)` | mark fields for contracts (filtered API variants) |
| `@interfaceObject` | add fields to every implementation of another subgraph's entity interface |

Others exist (`@composeDirective`, `@authenticated`, `@requiresScopes`, `@policy`, `@context`, `@cost`,
`@listSize`); the version you link decides which. Reference: Apollo's directive reference, saved in the workbench.

### Composition

Composition merges subgraph SDL into a **supergraph** (the API plus `join__` directives telling the router who
resolves what) and checks: shareability, key consistency, satisfiability (every field reachable), overrides,
externals. Tools: Rover (Apollo; it asks you to accept the Elastic License 2.0 for its composition plugin), Hive CLI, and
[@theguild/federation-composition](https://github.com/graphql-hive/federation-composition) (MIT, 0.27.0, supports
v2.0 to v2.9), which the course's tests use. `bin/course rover supergraph compose --config supergraph.yaml`
runs Rover on the same file, to compare: same rules and error codes, but Rover does not carry `@oneOf` into the
supergraph (Module 15 README). An open standard is in progress: the GraphQL Foundation's Composite Schemas
working group, roadmap at the "Proposal Stage".

## Check

1. reviews returns `Review.author` with `handle`. Why can that save a step?
2. What does `@requires` cost?
3. Why must the old owner keep the field while `@override` is in place?

<details><summary>Answers</summary>

1. `@provides(fields: "handle")` tells the router reviews already returns it on that path, so it does not ask
   accounts.
2. A step: the router fetches the required field from its owner first, then calls the requiring subgraph with it.
3. So a rollback (or the share of traffic still routed to it under a percentage) keeps working; remove it in a
   later deploy.
