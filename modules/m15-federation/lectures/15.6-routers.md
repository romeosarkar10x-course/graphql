On the JVM, the router is usually not Java: the subgraphs are.

### Production configuration

The same four rules in both dialects (lab 15.6):

| Rule | Apollo Router | Hive Router |
|---|---|---|
| forward headers | `headers.all.request: [{ propagate: { named: authorization } }]` | same shape |
| no introspection | `supergraph.introspection: false` | `introspection: false` |
| plans private | omit `plugins.experimental.expose_query_plan` | omit `query_planner.allow_expose` |
| subgraph timeout | `traffic_shaping.all.timeout: 2s` | `traffic_shaping.all.request_timeout: 2s` |

Apollo redacts subgraph errors by default ("Subgraph errors redacted"); Hive returns
`SUBGRAPH_REQUEST_TIMEOUT` with the service name. Health: Apollo on a separate listener (`127.0.0.1:8088/health`),
Hive on `/health`. Hive reads its config from `ROUTER_CONFIG_FILE_PATH` (a `--config` flag is ignored).

### Telemetry

Apollo Router collects anonymous usage telemetry unless started with `--anonymous-telemetry-disabled` (env
`APOLLO_TELEMETRY_DISABLED`); the course leaves the default alone, decide for your environment.

## Experiment (15 min)

Measured (2000 requests, 16 concurrent, local subgraphs, one laptop): Apollo p50 5 ms, p95 16, p99 29, 290 MB;
Hive p50 3, p95 5, p99 12, 151 MB. Run it yourself: one workload, not a benchmark.
