# 3.3 Custom scalars

## Hook (2 min)

The starter ISBN scalar in lab 3.3 accepts `{isbn: "9780441478125"}`, an *object*, as a valid ISBN when
it arrives as a variable, and rejects it as a literal. Same scalar, same input, two answers. Coercion has
three entry points, and they drift apart unless you make them share one function.

## Concept (15 min)

### Three methods, three paths

| `Coercing` method | When | From | Throw |
|---|---|---|---|
| `serialize` | execution, producing output | your Java value | `CoercingSerializeException` |
| `parseValue` | variable coercion | a JSON value (String, Number, Map, List, Boolean) | `CoercingParseValueException` |
| `parseLiteral` | validation and execution | an AST `Value` (`StringValue`, `IntValue`, `ObjectValue`...) | `CoercingParseLiteralException` |

Rules that keep them consistent: check the **type** first and reject what you do not accept; then call
**one** normalise/validate function; `serialize` must reject bad values (the output is a promise).

### `@specifiedBy`

`scalar ISBN @specifiedBy(url: "...")` (RFC #649, spec since 2021) points clients and tools at the
format. Introspection exposes it as `specifiedByURL`.

### Ready-made scalars

graphql-java-extended-scalars 24.0 (course-pinned, runs on graphql-java 26.1): `DateTime` (RFC 3339 with
offset), `Date`, `GraphQLLong`, `GraphQLBigDecimal`, `Url`, `Json` and more. Each must be both declared
(`scalar DateTime`) and registered (`.scalar(ExtendedScalars.DateTime)`).

## Java build (25 min)

Lab 3.3: an `ISBN` scalar that accepts ISBN-10 or ISBN-13 (hyphens allowed), validates check digits,
and always outputs 13 digits; plus `DateTime`, `BigDecimal` and `Url` in the same schema.

## Experiment (15 min)

Feed 15 bad inputs as literal and as variable; tabulate which path rejects what, first with the starter,
then with yours.

## Check (3 min)

1. Which method sees `9780441478125` written without quotes in the query?
2. Why is `Character.isDigit` the wrong test for ISBN digits?

<details><summary>Answers</summary>

1. `parseLiteral`, as an `IntValue`. It should reject it: ISBNs are strings.
2. It accepts non-ASCII digits (Arabic-Indic, full-width), which no ISBN contains.
</details>
