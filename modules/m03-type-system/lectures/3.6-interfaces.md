# 3.6 Interfaces

## Hook (2 min)

`node(id: "c1")` can return a club, a user, a book or a review. graphql-java gets back a Java object and
has to say which GraphQL type it is. It will not guess: it refuses to start.

## Concept (15 min)

### Shared fields, many types

```graphql
interface Node { id: ID! }
interface Reviewable implements Node { id: ID! averageRating: Float }   # RFC #373
type Book implements Reviewable & Node { id: ID! title: String! averageRating: Float }
```

- An object type implementing an interface must have every interface field, with a compatible type.
- An interface can implement interfaces (spec since 2021). Implementers must list the **whole** set:
  `Book implements Reviewable & Node`, not just `Reviewable`.
- Queries select shared fields directly and specific ones with fragments:
  `node(id: $id) { id ... on Book { title } ... on Timestamped { createdAt } }`.

### Type resolvers

A field of interface (or union) type needs a `TypeResolver`: Java value in, `GraphQLObjectType` out.

```java
TypeResolver byRecord = env -> env.getSchema().getObjectType(switch (env.getObject()) {
    case Data.Book b -> "Book";
    case Data.Club c -> "Club";
    default -> throw new IllegalStateException("no GraphQL type for " + env.getObject());
});
```

graphql-java checks at schema build time that **every** interface and union has one:
`There is no type resolver defined for interface / union 'Node' type`. (Spring for GraphQL, Module 6,
registers a class-name-based resolver for you.)
