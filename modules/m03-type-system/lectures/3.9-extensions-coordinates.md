# 3.9 Directives, extensions, deprecation, coordinates

## Hook (2 min)

Four teams own Shelfie's schema. One file means four teams in every pull request. Extensions let each
team own its file; coordinates let tools name any element in it with one string.

## Concept (15 min)

### Extensions

`extend type Query { clubs: [Club!]! }` adds to a type defined elsewhere (also `extend interface`,
`union`, `enum`, `input`, `scalar`, `schema`). graphql-java merges files with
`TypeDefinitionRegistry.merge`; an extension of a type that exists nowhere fails: `The extension 'Nope'
type is missing its base underlying type`. Federation (Module 15) builds on the same idea across services.

### Deprecation everywhere

`@deprecated(reason: "...")` on **fields, arguments, input fields and enum values** (arguments and input
fields: RFC #525, in the September 2025 spec; graphql-java supported it earlier). A required argument or input field (non-null, no default)
cannot be deprecated: graphql-java says `Required argument 'old' on field 'x' cannot be deprecated`.
Introspection hides deprecated items unless asked: `fields(includeDeprecated: true)`, likewise `args`,
`inputFields`, `enumValues`. Always give a reason that names the replacement.

### Schema coordinates (September 2025 spec)

| Element | Coordinate |
|---|---|
| type | `Club` |
| field or input field or enum value | `Club.owner`, `CreateReviewInput.rating`, `Visibility.PUBLIC` |
| argument | `Club.members(first:)` |
| directive, directive argument | `@deprecated`, `@deprecated(reason:)` |

One element, exactly one coordinate: the key for lint configs, usage metrics, docs, changelogs.
`bin/course gql coordinates <schema> <coordinate>...` resolves them.

### Directives on directive definitions

RFC #1206, accepted in 2026: `directive @tag(name: String!) @meta on FIELD_DEFINITION`. Not in the
September 2025 spec; graphql-java 26.1's parser rejects it (`offending token '@'`).
