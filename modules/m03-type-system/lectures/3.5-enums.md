# 3.5 Enums

## Hook (2 min)

Shelfie adds `ABANDONED` to `ReadingStatus`. The server is fine. Every Android app from last month crashes
on the shelf screen of anyone who abandoned a book.

## Concept (12 min)

### Names outside, values inside

An enum value has a **name** in the schema (`PRIVATE`) and an **internal value** your code sees. In
graphql-java an `EnumValuesProvider` maps names to values, used both ways: arguments arrive as internal
values, internal values serialise as names.

| Provider | Internal value |
|---|---|
| none | the name, as a String |
| `NaturalEnumValuesProvider<>(MyEnum.class)` | the Java enum constant of the same name |
| a lambda `name -> ...` | anything, e.g. the legacy code `"X"` |

A Java value with no GraphQL name fails to serialise: `Unknown value 'ABANDONED'`. That loud failure is
correct: a server must not emit what its schema does not declare.

### Evolving enums

Adding a value is "non-breaking" for the schema and **breaking for clients that receive it** into a
closed type: Java/Kotlin/Swift enums with strict decoders, exhaustive `switch`. Defences:

- clients: an `UNKNOWN` fallback (Jackson 3: `EnumFeature.READ_UNKNOWN_ENUM_VALUES_USING_DEFAULT_VALUE` +
  `@JsonEnumDefaultValue`; Apollo Kotlin generates `UNKNOWN__`);
- servers: document that values may be added; deprecate (`@deprecated` on an enum value) before removing.

## Check (3 min)

1. With no provider, what does a data fetcher receive for the argument `visibility: PRIVATE`?
2. Is removing an enum value ever safe?

<details><summary>Answers</summary>

1. The String `"PRIVATE"`.
2. Only after deprecation and evidence (usage metrics) that no client sends it; clients that *send* a
   removed value get validation errors.
