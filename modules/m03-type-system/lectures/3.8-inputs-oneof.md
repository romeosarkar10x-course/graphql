# 3.8 Input types and `@oneOf`

## Hook (2 min)

`book(id: ID, isbn: String, title: String)`. A client sends id *and* title. Which wins? The resolver's
`if` order, which no client can see. `@oneOf` moves that rule into the schema.

## Concept (15 min)

### Inputs are not outputs

Arguments and input-object fields use **input types**: scalars, enums, `input` objects and lists of them.
An `input` cannot have arguments, cannot implement interfaces, cannot be a union member. Output types
cannot be arguments. Mutation inputs (Module 4.2) are built from these.

### `@oneOf` (RFC #825, September 2025 spec)

```graphql
input BookLookup @oneOf { id: ID  isbn: String  title: String }
```

Exactly one field, with a non-null value. Every field must be nullable and have no default. Where the
rule runs in graphql-java 26.1 (lab 3.8's table):

| Input | Stage |
|---|---|
| `{}` or two keys in a literal | validation |
| `{id: null}` literal | execution (argument coercion), field error |
| two keys or a null key in a variable | variable coercion |
| `{id: $i}` with `$i: ID` absent | execution |

### Inhabitability (RFC #1211)

`input A @oneOf { a: A }` has no finite value: every A must set its only field to another A. The spec
now requires every oneOf input to be inhabited, and graphql-java 26.1 rejects the schema: `OneOf Input
Object A must be inhabited but all fields recursively reference only other OneOf Input Objects forming
an unresolvable cycle.` Plain inputs have a similar rule for non-null cycles (`input A { a: A! }`).

## Java build (20 min)

Lab 3.8: `BookLookup @oneOf`, a resolver that switches on the single key, 14 valid and invalid lookups.

## Experiment (15 min)

Try every invalid combination and fill the table. Then write `input A @oneOf { a: A }` and see
graphql-java 26.1 reject it; make it inhabited without removing the self-reference.

## Check (3 min)

1. Can a oneOf field be `ID!`?
2. Is `input A @oneOf { a: A, b: Int }` valid?

<details><summary>Answers</summary>

1. No: oneOf fields must be nullable (the "exactly one" rule replaces non-null).
2. Yes: `{b: 1}` (or `{a: {b: 1}}`) is a finite value.
</details>
