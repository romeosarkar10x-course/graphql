# 3.1 SDL and schema building

## Hook (2 min)

For three modules you have queried a schema someone else built. This module you build them, by hand,
with no framework: graphql-java turns a text file and a handful of lambdas into a server you can call
from `main`. One missing lambda, and a field returns `null` without a word of complaint.

## Concept (15 min)

### SDL in one screen

```graphql
schema { query: Query }          # optional when the root types are called Query, Mutation, Subscription

"Descriptions are strings before the element; GraphiQL and introspection show them."
type Query {
  club(id: ID!): Club            # a field with an argument
  clubs: [Club!]!
}

type Club {
  id: ID!
  members(first: Int = 10): [User!]!   # arguments can have defaults
}
```

- **Object types** have fields; each field has a type and optional arguments.
- **Root operation types** are the entry points: `Query`, `Mutation`, `Subscription`.
- `"..."` and `"""..."""` are **descriptions**, part of the schema (not comments: `#` is a comment).

### From text to an executable schema

| Step | graphql-java class | What it holds |
|---|---|---|
| Parse | `SchemaParser` | SDL text to AST |
| Collect | `TypeDefinitionRegistry` | All type definitions; several files `merge` into one |
| Wire | `RuntimeWiring` | Data fetchers per field, type resolvers, scalars, enum values |
| Generate | `SchemaGenerator.makeExecutableSchema` | A `GraphQLSchema`, checked for consistency |
| Run | `GraphQL.newGraphQL(schema).build().execute(...)` | An `ExecutionResult` |

### Data fetchers and the default

A **data fetcher** (resolver) produces one field's value from its parent (`env.getSource()`) and
arguments (`env.getArgument`). Fields without one use `PropertyDataFetcher`: a getter, record accessor
or map key **with the field's name**. `Club.name` works for free; `Club.owner` does not, because the
record has `ownerId`.

The generator checks types, interfaces and scalars. It does **not** check that every field can be
resolved.

## Experiment (15 min)

Delete one wiring entry for a nullable field, then for a non-null one. One fails silently, one loudly.
Then rename a field in the SDL only.

## Check (3 min)

1. Which step merges several `.graphqls` files?
2. Why does `Club.name` need no data fetcher but `Club.owner` does?

<details><summary>Answers</summary>

1. `TypeDefinitionRegistry.merge` (lab 3.9 does it with five files).
2. The default `PropertyDataFetcher` reads a property with the field's name: `Data.Club` has a `name`
   component but no `owner` one.
</details>
