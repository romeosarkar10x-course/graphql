# 3.7 Unions and Java sealed types

## Hook (2 min)

Add a sixth kind of feed event. In a codebase with `if (x instanceof A) ... else ...`, the new kind falls
into the `else` and is served as the wrong type. With a sealed interface and a `switch` without
`default`, the build fails on the line that must change.

## Concept (15 min)

### Union or interface

| | Interface | Union |
|---|---|---|
| Members share fields | yes, declared once | no (select everything by fragment) |
| Query without fragments | shared fields only | only `__typename` |
| Typical use | `Node`, `Timestamped` | search results, feeds, result types (4.3) |

Always select `__typename` on unions: clients use it to branch, and new members will arrive.

### Sealed interfaces of records

```java
sealed interface FeedItem {}                       // no permits: records in the same file
record ReviewPosted(String at, ...) implements FeedItem {}
record MemberJoined(String at, ...) implements FeedItem {}

TypeResolver r = env -> env.getSchema().getObjectType(switch ((FeedItem) env.getObject()) {
    case ReviewPosted p -> "ReviewPosted";
    case MemberJoined m -> "MemberJoined";
});                                                // no default
```

A switch expression over a sealed type must be exhaustive. Add a permitted record and `javac` reports
`the switch expression does not cover all possible input values`, at the type resolver.

## Java build (25 min)

Lab 3.7: `FeedItem` as a sealed interface of four records, an exhaustive type resolver; the test adds a
fifth record and expects the build to break. Mini-project 3 (records-to-SDL) reuses the idea in reverse:
the sealed interface *becomes* the union.

## Experiment (10 min)

Add a record without updating the switch; let the compiler catch it.

## Check (3 min)

1. Why must the switch's subject have the static type `FeedItem`, not `Object`?
2. A union gains a member. Which clients break?

<details><summary>Answers</summary>

1. Exhaustiveness is checked against the static type's permitted subclasses; `Object` is not sealed,
   so a `default` would be required.
2. Clients that assume a closed set: no fallback for unknown `__typename`.
</details>
