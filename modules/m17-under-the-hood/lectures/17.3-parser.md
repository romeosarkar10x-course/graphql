# 17.3 Parser, AST and fuzzing

## Hook (2 min)

`type T { u @s }`. graphql-java says: an object type with no fields, followed by a query. The spec says: a syntax
error. A fuzzer found that in 60 seconds. You will run that fuzzer against your own parser.

## Concept (20 min)

### Recursive descent

The syntactic grammar (appendix C.4) is LL(1) nearly everywhere: one token of lookahead picks the production. One
method per production:

```java
Selection selection() {
    if (at("...")) return fragmentSpreadOrInline();
    return field();
}
```

The few places that need more care: a Description (a string in front of a definition), `fragment on` (`on` is not
a fragment name), `[lookahead != {]` on fieldless types, and type-system extensions, which must add something.

### The AST as records

```java
public record Field(Loc loc, String alias, String name, List<Argument> arguments,
                    List<Directive> directives, List<Selection> selections) implements Selection {
    public String responseKey() { return alias != null ? alias : name; }
}
```

Records give `equals()` for free: comparing two trees is `==` on values. A sealed `Selection` with `Field`,
`Spread`, `Inline` lets every walker use an exhaustive `switch`:

```java
switch (sel) {
    case Field f -> ...;
    case Spread s -> ...;
    case Inline i -> ...;
}
```

### Fuzzing, differentially

**Jazzer** 0.30.0 (Code Intelligence, Apache-2.0) is coverage-guided fuzzing for the JVM, as a JUnit 5 test:

```java
@FuzzTest(maxDuration = "60s")
void parsersAgree(FuzzedDataProvider data) {
    String doc = data.consumeRemainingAsString();
    // parse with both; a crash in ours fails the test; a disagreement is saved for later
}
```

It instruments the bytecode (`jazzer.instrument` in `junit-platform.properties`), mutates inputs, and keeps those
that reach new branches. With `JAZZER_FUZZ=1` it fuzzes; without it, it replays its saved inputs as an ordinary
test. Three course findings: it needs the JUnit BOM to run on JUnit 6; without the instrumentation setting
coverage stays at 2 edges; and it uses about 2 GB.

Differential fuzzing turns "does it crash?" into "do the two agree?". Every disagreement is a bug in one of them,
or a place where the spec gives a choice.

## Check

1. Why does `extend scalar S` have to be rejected?
2. Why is `{}` legal as a query result but not as `type T {}`?
3. What can differential fuzzing never find?

<details><summary>Answers</summary>

1. `ScalarTypeExtension : extend scalar Name Directives[Const]`: the directives are required; an extension must
   add something.
2. A result can be an empty object (a fragment that does not apply); `FieldsDefinition` requires at least one
   field. (The draft, after RFC #1227, allows empty selection sets in documents.)
3. A bug both implementations share.

</details>
