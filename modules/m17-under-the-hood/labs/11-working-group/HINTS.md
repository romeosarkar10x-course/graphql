# Hints: 17.11 mock working group

1. Start from the spec text you would change: find the production or algorithm step, copy it, and edit the copy.
   An RFC that cannot point at the lines it changes is not ready for stage 1.
2. Compatibility has three audiences: documents that are valid today (do they change meaning?), servers that have
   not implemented it (what do they do with the new syntax?) and tools that print or store documents.
3. Read graphql-spec's guiding principles in CONTRIBUTING.md before the meeting ("favor no change", "simplicity
   and consistency over expressiveness and terseness"): the spec editor will.
