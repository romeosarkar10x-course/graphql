# 16.2 Registry and field analytics

## Hook (2 min)

`Book.isbn10` has been deprecated for months. Can you remove it? Static analysis cannot answer: the question is
about clients you do not control. A registry with field-level usage can say "no operation in 7 days; last used by
iOS 2.7.0, 8 days ago".

## Concept (15 min)

### What a registry does

Hive, GraphOS and Cosmo keep the published schema versions, check new ones against them (Module 13.5), and collect
**usage**: which operations ran, which fields and arguments they selected, from which client and version, how
long they took. The schema check then becomes usage-aware: removing a field nobody uses is safe.

### The report

Hive's usage report, version 2 (its JSON schema is in graphql-hive/console,
`packages/services/usage/usage-report-v2.schema.json`):

- `map`: one record per distinct document: `operation`, `operationName`, `fields`;
- `operations`: one entry per execution: `operationMapKey`, `timestamp` (ms), `execution` (`ok`, `duration`
  in ns, `errorsTotal`), `metadata.client` (`name`, `version`);
- sent with `X-Usage-API-Version: 2` and `Authorization: Bearer <token>` to `https://app.graphql-hive.com/usage`
  (the client library's default; self-hosted Hive has its own URL).

Hive's own collector lists type names, field coordinates, argument coordinates, and a `!` variant for arguments
given a non-null value (its tests show `Query.hello`, `Query.hello.message!`, `Query.hello.message`, `String`).
The course reports field and argument coordinates. Its stand-in collector checks the same shape. Nothing was sent
to Hive: no account.

### In Java

A graphql-java `Instrumentation` sees every execution. `beginExecution` returns a context completed with the
result. `QueryTraverser` lists the selected fields with their parent types. Reports are batched: Hive's JavaScript client buffers
operations in an agent (default `maxSize` 1,500 in its source) before it sends. Keep them when the endpoint is down, and drop them before memory runs out.

### Reading usage honestly

- **Window**: 7 days says "unused this week". A monthly batch job needs a 30-day window.
- **Coverage**: an operation type you do not report is invisible. In the probe, `Subscription.reviewAdded`
  came out unused because subscriptions were not in the replay. Hive has `subscriptionOperations` for them.
- **Clients**: traffic without a client name cannot tell you who to warn.

## Experiment (10 min)

List fields no client used in 7 days. Then 30. Which entry on the 7-day list is not dead at all?

## Check

1. Why does a report carry each operation's own timestamp, not the time it was sent?
2. Why is a document that fails validation not reported?
3. What would make "zero uses in 7 days" a wrong basis for removing a field?

<details><summary>Answers</summary>

1. Reports are batched and can be retried; usage windows are about when the request happened.
2. Hive needs at least one field per record, and an invalid document selected nothing in the schema.
3. A short window for a rare client, unreported traffic (subscriptions, other servers), or clients without names.

</details>
