# 16.1 Observability

## Hook (2 min)

Every Shelfie request is `POST /graphql`, status 200. An HTTP dashboard shows one flat, healthy line, even while
`BookPage` takes 350 ms and a partner burns a thousand times its usual cost. The game day (16.8) is unwinnable
with HTTP metrics. With metrics by operation, client and field, it takes minutes.

## Concept (15 min)

### Three questions, three labels

- **Which operation?** The `operationName` of the request. Clients that do not name operations show as
  `anonymous`, so name them (and persisted documents, Module 9, name themselves).
- **Which client?** A header such as `graphql-client-name` / `graphql-client-version` (Hive's convention; Apollo
  uses `apollographql-client-name`). Bound the values: a label taken raw from a header lets any caller create a
  new time series per request. Known names pass, the rest become `other`.
- **Which field?** The coordinate `Type.field`. A field name alone (`similar`) is ambiguous across types.

### What Spring for GraphQL and Boot 4 give you

Probed on Boot 4.2 / Spring for GraphQL 2.1:

- spans `http post /graphql` > `graphql query` > `graphql field similar` (non-trivial fetchers only) and
  `graphql dataloader` for batch mappings;
- metrics `graphql_request_seconds` (by operation **type** and outcome) and `graphql_datafetcher_seconds` (by
  field **name**).

Two convention beans (`DefaultExecutionRequestObservationConvention`, `DefaultDataFetcherObservationConvention`)
add the operation name, the client and the coordinate. Low-cardinality key values become metric labels and span
attributes; high-cardinality ones stay on spans. Errors are 200s, so count them yourself by `extensions.code`.

### Traces

Boot 4's `spring-boot-starter-opentelemetry` exports OTLP. Calls to dependencies become child spans only if their
clients come from Boot's builders (`RestClient.Builder`, which Boot 4 configures only with
`spring-boot-starter-restclient`). Sampling 100% is right for a lab, not for production: sample a share, keep
every error.

The **OpenTelemetry Java agent** (2.33.1 probed) needs no code. By default it gives three spans for the same
request: server, `query` with the document (arguments as `?`), and the HTTP client. With
`otel.instrumentation.graphql.data-fetcher.enabled=true` it adds one span per fetcher, named by field only.

### Grafana, Prometheus, Tempo

Prometheus scrapes `/actuator/prometheus`; histogram buckets (`percentiles-histogram`) let it compute p95 per
operation. Tempo stores traces; TraceQL selects spans by name, attributes and duration
(`{ name =~ "graphql field .*" && duration > 20ms }`). Probed on Tempo 3.1.1: a trace is readable by id at once,
but search finds it 20 to 30 s later.

## Check

1. Why must the client name be bounded before it becomes a label?
2. Why does `Book.reviews` not appear as a `graphql field` span?
3. Spring already times every request. What does a request metric without the operation name hide?

<details><summary>Answers</summary>

1. Each label value is a time series in Prometheus; a free-form header lets any caller create unbounded series.
2. It is a batch mapping: its time shows as the `graphql dataloader` span and the HTTP call under it.
3. Which operation is slow or failing: all of them are averaged into one series per outcome.
